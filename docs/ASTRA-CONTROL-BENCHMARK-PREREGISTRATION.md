## Four fixed arms and common input

| ID | Arm | Delivered package |
|---|---|---|
| `SOURCE` | Exact, unmodified source | Text equals source; no invented completion status. |
| `V15` | Frozen experimental V15 end-to-end editor, verifier and repair flow | Its own editor RAW, FINAL text, and existing visible disposition. This is experimental V15, not the deployed `reconstruction-v1` product. |
| `C_DOWNSTREAM` | Frozen post-V3 candidate C downstream on the exact V15 editor RAW | FINAL text with completed, incomplete, or abstained status and disclosure from its frozen implementation. |
| `ASTRA_DIRECT` | One independent GPT-6 Astra direct edit | The exact `edited_text` from one Astra response. It is not the Whodunnit RAW. |

Each generative editor receives the same informational content: SOURCE and OBJECTIVE. V15 uses its published editor prompt and deterministic features derived only from that input; Astra receives SOURCE and OBJECTIVE plus the frozen [minimal instruction](../data/evaluation/astra-control-fresh-48-v1/astra-editor-instruction.txt). Neither sees category, prelabel, safety trap, other output, or prior judgment. **Every V15/C case uses exactly `PRESETS.natural`; no case-specific profile, refinement or voiceprint is permitted.** V15's editor makes one call and its exact saved RAW is the sole candidate for V15 and C. C and V15 receive identical source, objective, profile and RAW for their downstream comparison. Their different prompts, schemas, verification choices and dispositions are the architecture bundles under test; this pair does not isolate any one module. Freeze the exact V15 editor and a common downstream verifier/repair provider, versions, settings, call budgets and independent per-arm calls before generation. V15's optional diagnosis is absent. Astra and Whodunnit have different prompts and editor models; their comparison estimates a **whole-system product gap**, not the isolated effect of the control layer on identical Astra prose.

V15 runs its published editor call. Its caller durably records and hashes the exact editor response before returning it to V15's downstream logic, without changing the request, response, or frozen implementation. C later receives that exact `candidate.text` as RAW. C's adapter must assert UTF-8 byte equality against the frozen V15 RAW and preserve the original response envelope. If V15's editor returns no valid candidate, retain that technical outcome; C has no RAW and receives no substitute or regenerated edit. Astra is independently generated once per case. This gives a clean C–V15 downstream pair while making the Astra gap an honest, differently generated frontier comparison.

## Astra direct execution contract

The planned supported surface is the OpenAI **Responses API** with `model: "gpt-6-astra"`, `reasoning: {"effort":"high"}`, `service_tier: "default"` for Standard service, `store: false`, `stream: false`, `truncation: "disabled"`, `max_output_tokens: 12000`, a 180000 ms client deadline, SDK/HTTP retries disabled, one fresh independent request per case, no previous response ID or conversation, and an empty tools array. The `reasoning.mode` field is **intentionally omitted** from the exact request; an executor may not add `standard` or any other value without a new protocol. Do not enable browsing, repository retrieval, code execution, file search, MCP, or any other external tool. Omit `temperature`, `top_p`, `top_k`, and logprob controls. OpenAI lists high effort and Responses/Structured Outputs support for Astra; its GPT-6 guide says temperature and top-p are unsupported when reasoning effort is enabled. The model page currently lists `gpt-6-astra` without a dated snapshot, so this is a **moving alias** unless provider evidence establishes otherwise. Account access, entitlement, and effective serving revision are unverified and are pre-generation blockers. No API call is made to resolve them during preregistration. [Astra model](https://developers.openai.com/api/docs/models/gpt-6-astra), [GPT-6 parameter guidance](https://developers.openai.com/api/docs/guides/latest-model), [Structured Outputs syntax](https://developers.openai.com/api/docs/guides/structured-outputs), [Responses API reference](https://developers.openai.com/api/reference/resources/responses/methods/create).

The exact instruction is the UTF-8 file's bytes with its one terminal LF removed; all other bytes are preserved. The request's `instructions` is that string. The only input is one user `input_text` item whose text is `JSON.stringify({source, objective})` with ordered keys `source`, then `objective`, using the original frozen strings without normalization or added fields. Encode that string as UTF-8. The raw source/objective bytes and resulting serialized request hash are recorded per case. The response format is `text.format: {"type":"json_schema","name":"astra_direct_edit_v1","strict":true,"schema":{"type":"object","properties":{"edited_text":{"type":"string"}},"required":["edited_text"],"additionalProperties":false}}`. Parse the one output object strictly, then require nonempty `edited_text` of at most 60000 characters locally. Do not trim, repair, coerce, select among alternatives, or ask again. Any refusal, incomplete response, malformed structure, empty/oversize text, timeout, or transport failure is a durable technical outcome; no replacement or retry. Record request ID, response model, response creation time/status, usage (including reasoning tokens if exposed), finish/incomplete reason, start/end timestamps, latency, attempt count, and available billing/cost metadata without secrets or credentials. An alias cannot prove an immutable remote revision; qualify model-identity claims accordingly.

The current frozen V15 and C code rejects live structured callers unless they are confirmed account-backed and zero incremental cost. A real compatible V15 editor and common verifier/repair runtime have **not** been fixed. Never mislabel a live paid caller as an offline/demo caller, weaken the published guard, or generate RAW before this is resolved. A separate pre-generation lock must prove the actual allowed runtime or stop this experiment. Astra direct spend must be independently authorized and recorded before any call; no amount is assumed here.

## Fresh 48-case corpus and prelabels

Four independent eligible creators author 12 synthetic SOURCE/OBJECTIVE pairs each, after this protocol and a custodian-only exclusion manifest are committed. The manifest resolves every excluded case-bearing file to a canonical path and records exact file SHA-256 and Git blob ID, content class, and the applicable exclusion; the custodian verifies its inventory before briefing. A creator who has seen excluded case-bearing material or its outcome analyses is ineligible. Freeze signed prior-access attestations first. Creators use isolated workspaces and conversations, cannot read repository outcomes or one another's drafts, and receive only a sanitized brief with workload categories, task schema, and assigned strata. It contains no excluded example, outcome or expected rewrite. The assignment grid is fixed in the machine protocol. The mutually exclusive primary strata total 48: 8 already-good/conditional restraint; 8 explicit supplied factual updates; 6 missing-value updates; 6 localized edits; 6 broad reconstructions; 5 voice-sensitive tasks; 5 collateral-change traps; 4 ambiguous/contested tasks. These are sampling targets, not outcome labels. Orthogonal frozen tags have numeric corpus floors: casual ≥8, professional ≥8, academic-ish ≥6, personal ≥6; synthetic-shaped ≥8, formulaic ≥8, overproduced ≥6; number/date/time ≥12, negation ≥8, certainty ≥8, causality ≥6, comparison ≥6, quotation ≥6, protected phrase ≥6. Tags may overlap. Require exactly 12 short (25–100 words), 24 medium (101–300), and 12 long (301–700) texts, and at least eight cases where doing almost nothing is defensible. All quotas are checked before corpus lock and cannot be relaxed after outcome generation.

Before corpus lock, the custodian screens every draft against the **prospectively committed exclusion manifest** and against every other new draft. Normalize with Unicode NFC, Unicode full casefold, and collapse each Unicode whitespace run to one ASCII space before trim. Tokenize normalized text into maximal contiguous Unicode letter/number runs; flag any common six-token contiguous shingle in SOURCE or OBJECTIVE, alongside exact UTF-8 hash and whole-field normalized equality. Compare all 48 drafts pairwise (1,128 unordered pairs), not just each against historical material. An independent human reviews semantic scenario and requested transformation overlap against the excluded inventory and across the new set, including all flagged peer pairs. A paraphrase of an old or peer fact pattern/editing trap is overlap even without a shingle. Freeze the screening implementation and Unicode/runtime version in the exclusion manifest; no overlap threshold is tuned to drafts. Preserve rejected draft hashes, reasons, reviewer disagreements and disposition without leaking excluded text to creators; replace drafts within assigned strata **before** case lock only. Freeze accepted case bytes, creator IDs, objective, primary stratum, tags, all screen results and hashes. Any overlap discovered after lock invalidates the confirmatory corpus; do not drop or replace a convenient case.

Two independent human prelabelers inspect only SOURCE/OBJECTIVE, separately and before any arm output. Each records intended objective, acceptable edit scope, facts and claims to preserve, explicitly authorized factual changes, names/numbers/dates/quotes/protected phrases, required form, whether no/minimal editing is expected, ambiguities and missing propositions, voice constraints, and every applicable zero-tolerance trap. They cite source/objective spans and do **not** write ideal prose. Freeze both original submissions and disagreements without reconciliation into model instructions. No prelabel reaches any editor, verifier, repairer, or initial blind judge.

## Generation, blind judgment, and audit

Freeze the corpus and both prelabels before either editor generates an output. Execute cases in ascending fixed case-ID order. For each case, run **V15, then C, then Astra**, without using earlier arm outcomes to alter later inputs or settings. V15 runs once through its frozen editor and downstream flow, durably recording the editor response before its downstream use; then freeze that RAW and V15 FINAL before C receives the exact RAW. Run C with an independent reviewer/repair invocation. Run one separate Astra direct request whether or not V15/C succeeded; neither editor sees the other's output. Persist exact application-level semantic request and response payload bytes for each model call, plus deterministic findings, review/repair/recheck attempts, FINAL, visible status/disclosure, traces, hashes, usage and cost. This means the exact caller arguments and returned model content, not raw HTTP traffic: do not capture or persist Authorization, Cookie, Set-Cookie, proxy credentials or raw HTTP headers. Persist only allowlisted nonsecret transport metadata (request ID, response model/status, timestamps, usage and billing data when available). Scan and strip any unexpected secret-bearing field before durable storage; a payload that cannot be stored with exact approved semantic fields intact is a technical failure and blocks advancement. Hash the exact UTF-8 bytes of every approved application-level payload and its durable copy; verify equality before downstream use. A stop or missing output remains in the 48-case accounting. No case, RAW, arm output, or judgment is replaced after its lock.

Before either FINAL, trace, arm mapping or status is shown to RAW judges, two independent blind human judges receive only SOURCE, OBJECTIVE and the identical frozen V15 editor RAW under an opaque ID. They classify it with cited source/RAW spans and identify each independently useful safe edit span and each material defect span. **GOOD** means at least one material objective-relevant beneficial edit and no material defect. **BAD** means at least one material harmful defect and no independently useful safe edit. **MIXED** means both an independently useful safe edit and a material harmful defect. **OTHER** means available text with neither a material benefit nor a material defect, including unchanged or trivial edits. **DISPUTED** means a material classification or span disagreement remains after a third independent blind adjudicator; missing/invalid RAW is a separate technical outcome, never OTHER. Freeze both original labels and the adjudication before exposing FINAL, traces, status or arm identity to these judges. A disagreement is preserved even if adjudicated. The shared RAW label applies to V15 and C; it does not label Astra's independent output.

The custodian assigns fresh opaque IDs and independently randomized per-reviewer order to 192 output packages after arm outputs lock. **Primary blind packets contain only opaque ID, identical SOURCE, identical OBJECTIVE, and output text** for every arm; they contain no status, disclosure, model, trace, prelabel, arm metadata or other judgments. Two independent human reviewers assess every text for meaning preservation, objective satisfaction (YES/PARTIAL/NO), writing quality, voice, factual integrity, restraint, unnecessary/harmful editing, collateral change, and text-only overall preference, with cited evidence. The five pairwise packets cover C–V15, Astra–C, Astra–V15, C–SOURCE, and Astra–SOURCE with independently randomized left/right orientation; each contains only SOURCE, OBJECTIVE and the two texts under opaque IDs. Astra never judges its own work as the sole judge. A SOURCE output is recognizable as unchanged when judges see SOURCE; identical arm texts can also reveal duplication. This unavoidable partial unblinding is disclosed and reviewer arm guesses are collected after primary ratings.

Freeze both original **text-only** submissions before exposing status or disclosure to reviewers. Then use a separate secondary product-package tier with the same opaque IDs and text plus the arm's actual visible status/disclosure. Review completion claims, honest incompleteness/abstention, stale facts presented as completed, and product-package preference. Freeze both original secondary submissions before any mapping or trace join. A third independent blind adjudicator examines every material safety disagreement, preserving original labels; do not force a pass. Only afterward may a custodian join arm identity, traces and prelabels, and audit **all 48 cases** for classes 5 and 6 by comparing RAW defect spans, repair attempts and FINAL, including missing and technical outcomes. For BAD or MIXED RAW, the defect-escape denominator is every evaluable BAD∪MIXED case; the numerator is cases with at least one preidentified material RAW defect accepted into FINAL, reported per arm and defect span. Missing or disputed RAW cases remain separately visible and cannot shrink the planned 48-case denominator for advancement. If material safety disagreement remains unresolved, advancement is INCONCLUSIVE. Report text-only and product-package results separately, with all reviewer disagreements and per-case evidence. No deterministic failure is overridden by prose preference.

## Outcomes and advancement

The six **separate zero-tolerance** classes are: (1) stale current facts presented as completed after an authorized update; (2) invented missing replacements; (3) collateral unauthorized factual mutations; (4) material unauthorized meaning changes; (5) confirmed materially bad Whodunnit RAW edits reaching FINAL; and (6) accepted harmful repairs. Count each applicable class and unique affected cases per arm; never bury one in an average. Classes 5 and 6 are **not applicable** to Astra direct, which has no Whodunnit RAW/repair stage; do not record this as zero catches or zero repair harm. SOURCE is an unedited reference, so edit-induced safety classes are not applicable to it; its unmet objectives and original-source risks remain visible in descriptive comparisons. Astra's direct output remains fully accountable for classes 1–4 and its own factual, meaning, objective and voice defects. Separately record Astra unsupported invention, meaning drift, excessive rewrite, objective miss, factual mutation, stale update, voice destruction, certainty shift, causal invention, and number/date error. An Astra error is evidence about direct editing, not ground truth for Whodunnit.

Report materially GOOD, BAD, MIXED, OTHER and DISPUTED RAW separately; materially good FINAL; GOOD-RAW→FINAL retention/loss; MIXED safe-span retention and BAD∪MIXED defect escape; objective and explicit-update completion; unnecessary fallback/editing; already-good restraint; voice harm; meaning/factual/collateral failure; six safety classes; accepted/rejected repairs; primary blind text-only writing-quality and overall **safe** preference; and secondary product-package preference/status integrity. A GOOD-RAW retention numerator counts a case only when at least one preidentified material beneficial RAW edit survives in FINAL **and** the entire FINAL is independently judged meaning-, fact-, scope- and voice-safe, with no material newly introduced harmful defect or false-complete claim. A MIXED safe-span retention numerator likewise requires at least one preidentified materially beneficial RAW edit to survive in a wholly safe FINAL, with **neither** a preidentified RAW defect **nor** any newly introduced material harmful defect or false-complete claim surviving. Count cases and report per-span detail. An abstention, fallback to source, or merely harmless FINAL without a retained beneficial edit is not retention. Show numerator, denominator, missing cases, disagreement, paired transition table, and primary stratum for every metric. Also record wall-clock latency, model/verifier/repair calls, retries (including attempted hidden transport retries if known), token usage and incremental cost per case and arm. Do not claim an unknown cost is zero.

The five required paired comparisons are C–V15 (primary architecture comparison), Astra–C (frontier gap), Astra–V15, C–SOURCE, and Astra–SOURCE. Report C vs Astra in mutually exclusive strata: both safe with C preferred/Astra preferred/tie/neither; C unsafe/Astra safe; Astra unsafe/C safe; both unsafe; and missing/unresolved. **Both safe** means both FINAL texts have an adjudicated absence of material unauthorized meaning/factual/collateral defects and false completion claims, with no applicable class 1–6 failure after secondary package and trace audit. Honest objective incompletion may still be safe; material voice harm is tracked separately and blocks C advancement. Any unresolved material safety judgment or missing output goes in missing/unresolved, not both safe. On both-safe cases, the frontier preference share is `(C preferred + 0.5 × tie) / all both-safe adjudicated cases`; `neither` contributes zero. This share never absorbs unsafe cases. SOURCE comparisons are descriptive controls, not advancement shortcuts.

Candidate C advances only as an **experimental architecture for a later independent holdout** if all of these prespecified descriptive pilot gates pass. Every one of the 48 cases must have an evaluable frozen RAW, V15/C/Astra FINAL or explicit absence, two original RAW labels, primary and secondary judgments, adjudication as needed, and an all-arm trace/custody audit; a technical absence or unresolved material label means **INCONCLUSIVE**, never a smaller positive-advance denominator. At least 16 RAW cases must be confirmed GOOD, at least six of the eight supplied-update RAWs must correctly apply their authorized update, at least three RAWs must be BAD∪MIXED, and at least three must be MIXED; otherwise the architecture mechanism is untested and advancement is INCONCLUSIVE. C GOOD-RAW retention must show at least five net paired case gains, at least 15 percentage-point improvement over V15 on the common GOOD denominator, and at most one V15-retained/C-lost case, using the wholly safe FINAL numerator defined above. On MIXED RAW, C must retain a safe edit in a wholly safe FINAL in at least two more cases than V15 and lose **zero** MIXED cases where V15 did so. C must have at least four net case gains in objective **YES** versus V15 and at least two net cases with a correctly completed authorized update among the eight supplied-update cases, with no increase in false-complete visible dispositions. There must be zero confirmed failures in each of the six safety classes, zero material voice harm in C FINAL, zero harmful edit of an already-good source in C FINAL, and no unresolved **material** safety, authorization or RAW-span dispute. C's unnecessary edits on already-good cases must be no more numerous than V15's. Among at least 20 both-safe adjudicated C/Astra cases, C's frontier preference share must be at least 0.40. Any confirmed zero-class failure is **FAIL**. An evaluable but unmet product gate is **NO ADVANCEMENT**. Missing required denominator or unresolved judgment is **INCONCLUSIVE**; integrity deviations follow the invalidation rules below. These thresholds are screening rules, not power to establish statistical superiority. Zero failures in 48 cases cannot prove rare-event or universal safety. No threshold, denominator, stratum or failed case may be changed after outputs.
