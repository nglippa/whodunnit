# Experimental semantic scope calibration

Production remains `reconstruction-v1`. Published v5 and v6 behavior and semantic-review.v2 are retained. `reconstruction-v7` is an experimental decision boundary using semantic-review.v3. No frozen holdout, local model, reconstruction benchmark, deployment, or paid API was used in this pass. This is **development evidence**, not proof of generalization.

## Scope definition and four decision states

`SUBSTANTIVE_RECONSTRUCTION` means an interdependent writing problem across enough of the document that isolated span repairs cannot make a coherent revision. Evidence may include repeated propositions across sections, weak information progression, organization obscuring the message, or globally repeated rhetorical function. Length, formality, many independent local defects, or missing facts alone do not qualify.

V7 separates a **validated reviewer diagnosis** from feasibility and execution. “Validated” means schema and source citations passed; it does not mean editorial truth was independently proved.

| Diagnosis | Feasibility | Execution |
| --- | --- | --- |
| Leave alone | No edit needed | Return source |
| Local or distributed light | Safe with source | Edit within scope |
| Substantive | Safe with source | Substantive candidate, then independent verification |
| Substantive | Partial only or needs information | `BLOCKED_PENDING_INFORMATION`; return source |

The last row preserves the substantive diagnosis internally even though no rewrite is executed. A high-confidence, grounded `NEEDS_INFORMATION` review can also block narrower execution; when the reviewer says it cannot improve safely, the planner does not use missing facts as permission to invent. On review failure, V7 falls back to deterministic planning. V6 retains its old reconciliation policy for reproducible comparison.

Semantic-review.v3 adds a strict `rewriteFeasibility` field (`SAFE_WITH_SOURCE`, `PARTIAL_ONLY`, `NEEDS_INFORMATION`) while retaining the v2 disposition and exact source-span contract. Its prompt clarifies that safe, meaning-preserving compression can be possible even when more facts would make the piece better. It asks the reviewer to map paragraph information roles and explain cross-section restatement. V2 prompt and schema remain pinned; V3 prompt has its own fingerprint test. Neither reviewer generates final text or overrides protected facts and independent verification.

`semanticProgressionMap` prototypes a bounded paragraph map and possible restatement links. It accepts reviewer-provided paragraph roles and makes a `POSSIBLE_RESTATEMENT` edge only from a distributed redundancy finding that cites multiple paragraphs. An edge is a cited hypothesis, not deterministic proof of semantic equivalence. No count of roles or edges automatically chooses editing scope. The v3 controls supplied complete role maps on 24/24 documents; cited restatement links appeared in six of eight substantive controls, zero of eight clean controls, and one distributed-light control. Healthy elaboration can have repeated vocabulary without such a link, and an absent link does not prove health.

## New adversarial development controls

An isolated creator authored [12 near-minimal pairs](../data/fixtures/semantic-review-development/substantive-controls.json), 24 documents total. A separate blind red-team annotator agreed with the creator on 24/24 dispositions: eight leave-alone, eight substantive, four local, two distributed light, and two insufficient context. Pairs cover healthy progression versus restatement; legitimate policy, procedure, and executive-summary repetition versus empty loops; one, three and six weak paragraphs out of eight; missing facts versus editable wording; and sound critiques quoting bad prose. Perfect agreement on authored controls is a limitation: they may be too legible to both annotators.

Two account-backed agents of **one model family** reviewed disjoint halves using the pinned v2 contract and deterministic preliminary requests. Two other account-backed agents of that same family reviewed the halves with v3. No metered provider API was called. The [v2 reviews](../data/fixtures/semantic-review-development/substantive-controls-v2-reviews.json), [v3 reviews](../data/fixtures/semantic-review-development/substantive-controls-v3-reviews.json), and separate result files allow replay with `tools/eval/substantive-controls.ts`. Agent sessions did not provide reliable provider token, model-setting, or latency metadata, so these are contract probes, not a provider benchmark or cross-family validation.

The [experiment manifest](../data/fixtures/semantic-review-development/substantive-experiment-manifest.json) records account-agent roles, exact contract versions, routing mode, request-generation command, unavailable model-setting fields, and SHA-256 hashes. The saved v2/v3 request bundles contain the exact synthetic source and deterministic-plan messages supplied to reviewers; no gold labels were sent. A unit test checks artifact hashes. The model ID and sampling settings were not exposed by the account-agent interface, limiting exact replay on another provider.

V2 and V3 dispositions agreed on 23/24 controls; safe-to-rewrite flags agreed on 17/24, and the presence of missing-information entries agreed on 20/24. These are **contract comparisons within one model family**, not independent model-family agreement. V3's one substantive miss was `P08-B`, where six of eight paragraphs were circular but the reviewer selected distributed light. Both contracts conflated two cases needing context with clean writing; execution stayed unchanged, but the diagnosis was wrong. V2 clean validation failed because it required a `brakeReason` whenever clean counterevidence was present, even when there was no local finding to veto. V3 allows such counterevidence; a real brake still needs a reason during reconciliation.

Only after the review-all comparison, the pinned selective router was applied to these controls: 13/24 would route, including six of eight substantive cases. It would obtain substantive diagnoses on five of eight, versus seven of eight with review-all. Seven of 14 edit-labeled controls would execute an edit under selective routing, versus 11 of 14 with review-all; three of the latter were appropriately blocked pending facts. This is a development-only illustration of routing recall loss, not a reason to tune the router against these controls.

V7 introduced no new local writing rules. It does not treat a reviewer’s confidence, paragraph count, or graph edge count alone as authority. The original semantic-preservation checks still run after any candidate; blocked documents never enter reconstruction. The normal web route remains v1. No UI or browser flow changed.

An independent account-backed red team found four concrete architecture defects. V7 initially allowed a missing-information review to cancel an unrelated hard deterministic or user-requested edit; it now limits execution to that independent local work. A forced-model evaluation could bypass a blocked decision; blocked execution now returns the source even with `forceModel`. V3 substantive evidence could be assembled from unrelated findings; V7 now requires **one** major, confident distributed finding citing at least two paragraphs, while V6's published v2 policy remains pinned. V3 also now validates the prompt's neutral feasibility state for leave-alone and insufficient-evidence reviews. The red team confirmed the known `P08-B` substantive miss and the two missing-context misdiagnoses; those remain development failures, not phrase-specific fixes. It found no raw source text in the new telemetry fields. Its cost-guard concern was that Groq's free-quota status is asserted by the operator rather than automatically verified; the command remains deny-by-default without that assertion.

## Cost, privacy, and limitations

The evaluation CLI now preflights frontier, worker, and judge routes. Demo and loopback are allowed; potentially metered remote routes are denied by default even if a key exists. `--allow-paid-provider` requires separate explicit authorization; `--confirm-free-groq` asserts that the operator has verified a genuinely zero-cost quota and applies only to Groq. Neither flag was used here. The development replay CLIs import no provider. Prior approximately **$2.73 Claude consultation spend was a process failure** and was not repeated. This pass used account-backed subordinate agents only, with no incremental paid API calls.

Telemetry records contract version, route, model identifier when supplied, token/cost fields when supplied, diagnosis, feasibility, execution decision and latency. It excludes source text, excerpts, rationales and missing-information content. Synthetic artifacts contain quotations only from newly authored development documents. A `StructuredCaller` currently lacks a transport abort signal, so a logical review timeout discards a late answer but may not stop the underlying request.

The account-backed agents did not supply a second model family. Two missing-context controls were misdiagnosed as clean, and one distributed substantive control was under-scoped. Original development labels are inconsistent with the operational definition. The new controls are small and were constructed for this experiment. **Holdout V3 is NO-GO.** Next: use a separately verified zero-cost second family, if available, to run pinned v3 review-all on a fresh development set with more genuinely ambiguous scope and missing-information cases. Audit each family independently, then evaluate selective routing. Only after the contract and routing policy stabilize should an independent team freeze Holdout V3.
