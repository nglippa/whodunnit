It authorizes no model call, RAW generation, spend, downstream run, or amendment of a frozen byte sequence.

## One shared editorial request

For each frozen case, send only its SOURCE and OBJECTIVE strings to one standard frontier editor. The user payload is a JSON object with exactly `source` and `objective` string fields; do not add case IDs, strata, tags, prelabels, plans, protected inventories, voiceprints, expected prose, hypotheses, or downstream findings. The system prompt is the exact UTF-8 LF bytes of [`raw-editor-prompt-v1.txt`](../data/evaluation/post-v3-comparison/raw-editor-prompt-v1.txt), including its final newline. Its exact file SHA-256 is `0e05f84297407b68d8e642f3944a00fa8fb9369a5c2c0696bbde196db688994c`.

Require one JSON object containing exactly one field, `text`, a nonempty string of at most 60,000 characters. Reject unknown fields, missing or empty text, malformed JSON, and a model or schema mismatch. The output contract contains no explanation, change list, score, verifier prediction, alternative, or second candidate. Returning unchanged SOURCE is a permitted RAW editorial choice; it does not declare that the objective is complete. Completion is assessed separately in downstream output review. The response is untrusted and must pass the strict, separately versioned RAW response schema before its text is saved. The saved RAW is the exact response text and provenance produced by the single authorized attempt. A failure remains a recorded failure; no editorial retry, substitute model, regenerated RAW, demo output, or silently chosen fallback is allowed.

The published V15 editor uses `RECONSTRUCT_SYSTEM_V8`, `candidateSchema`, and planning context. That published prompt requests a `changes` array and refers to a protected inventory, so it is not the source/objective-only RAW request. This document creates a distinct evaluation-only prompt version; it does not change the published prompt registry, V15, or its frozen hash. The downstream adapter presents the one saved RAW text to V15's existing candidate boundary as `{text: raw, changes: []}`. The empty array is adapter shape only; it is not a new model-authored explanation or candidate. Arms A–D and V15 must consume identical saved SOURCE, OBJECTIVE, and RAW bytes and hashes, without invoking another editor.

## Caller identity and settings amendment

The predecessor operational manifest requires a pre-call proof that alias `sonnet` resolves to `claude-sonnet-5-5` and that every effective sampling setting is observable and pinned. CLI 2.1.288 exposes no demonstrated read-only way to prove that alias resolution or inspect provider/CLI defaults before a request. The current instruction authorizes a narrow, prospective supersession of those two pre-call requirements for RAW generation only. The requested model is the exact identifier **`claude-sonnet-5-5`**, not the moving alias `sonnet`; the required CLI remains **2.1.288** and effort is pinned to **`medium`**. The first actual corpus request is the first possible resolution check. If its response reports a different resolved model, a fallback, or no auditable resolved identity, preserve that one attempt as a technical failure and hard-stop all further RAW generation. Do not accept it, retry it, or regenerate that case. A different CLI version, account mode, or provider remains a pre-call hard stop.

Before any request, freeze the exact CLI invocation and adapter source hash, the account-safe environment policy, prompt bytes and hash, request-schema bytes and hash, output parser, structured-output mode, tool/MCP/network and permission configuration, session persistence, timeout, and one-attempt/no-retry behavior. The RAW adapter pins a **120-second timeout** (terminate, then kill if necessary), `MAX_STRUCTURED_OUTPUT_RETRIES=0`, and `CLAUDE_CODE_MAX_RETRIES=0`; neither a timeout nor malformed response permits retry. Record the following setting classes separately:

| Class | Required treatment |
| --- | --- |
| Explicit controls | Pin exact CLI flags and values, including full model identifier, effort/thinking when exposed, output format, JSON schema, tools, settings sources, and safe/restricted mode. |
| CLI-exposed effective controls | Observe and pin their exact values before a call. A mismatch remains a hard stop. Never infer a value from historical usage. |
| Provider/CLI defaults not exposed | Record each such control, including temperature, top-p, top-k, and maximum output tokens when unavailable, as `PROVIDER/CLI DEFAULT—NOT OBSERVABLE`; do not invent numeric values. This is an explicit reproducibility limitation accepted by this additive amendment, not a pre-call hard stop. Keep the same CLI version, request contract, and explicit controls for every case. |
| Inherited or managed controls | Isolate or pin settings that the CLI exposes and that could alter model routing, retry, tools, network, or sampling. Record any unobservable managed/provider behavior as a limitation; a known conflicting override is a hard stop. |
| Runtime provenance | Record actual resolved model, CLI version, request and response hashes, timestamps, usage/spend information, and all attempt outcomes. A response showing a different model, fallback, or no resolved identity stops further generation and is retained as a technical failure. |

This amendment supersedes only the predecessor manifest's instruction to hard-stop when **pre-call alias resolution** or **unexposed provider/CLI defaults** cannot be observed. It does not relax account-backed $0 access, explicit settings, CLI version, structured schema, attempt budget, model identity acceptance, provenance, or no-fallback rules. A CLI help screen listing possible flags is not proof of effective values. A first response cannot retroactively make a mismatched attempt valid.
