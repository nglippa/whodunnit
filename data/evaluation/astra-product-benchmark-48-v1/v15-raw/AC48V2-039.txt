Naming new sound recordings

Why this is changing
Over the past month, editors have found files whose names say little about their contents. In two instances, a filename described a closing door even though the file contained footsteps followed by a closing door. This does not make the recordings unusable, but it makes choosing an excerpt slower.

Who and what this applies to
- Use this naming arrangement for recordings made from 1 August onward.
- You do not need to rename existing files.

How to name a new file
1. Begin with the session code. The recording coordinator assigns it. Do not invent a second code because the first one seems unmemorable.
2. Add a brief description of the audible action. Describe the action, not its imagined use. A kettle boiling should not be named as a spaceship engine merely because somebody thinks it could serve that purpose.
3. End with the take number.

If you cannot identify the action confidently, describe what you can hear without claiming to know its source. You can mention a possible source in the notes, as a possibility.

What goes in the notes
Put the location, equipment, and any unusual recording conditions in the text notes. The filename does not need to contain these details.

Existing files
- You may rename an old file when you use it in a project. If you do, enter the original filename in the accompanying notes. Earlier project documents may still refer to the old name.
- Files already delivered to an outside client keep their delivered names.

Unresolved: sessions recorded jointly by two teams
We have not agreed how to name these sessions. Until that is settled, ask the coordinator for a code before uploading the files. The coordinator will keep a list of those sessions so they can be reviewed together later.

Initial checks
- The coordinator will check the first five new uploads from each team and flag naming problems.
- This check covers filenames and notes only. It is not an assessment of recording quality, and it does not replace the separate check required before a file is delivered to a client.
